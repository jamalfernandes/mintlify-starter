Most of the main flow is user-invocable only. An agent asking for `/to-spec` or `/grill-with-docs` is refused, deliberately: alignment is human-in-the-loop, and an agent that can start its own planning will.

If you cannot remember which one fits, `/ask-matt` is the router.

## The main flow

| Skill | Stop | What it does |
| --- | --- | --- |
| `/new-project` | 1 | Scaffolds the repo, Linear project and Nostos entry, then grills phases 0 to 3 into a product spec |
| `/grill-with-docs` | 4 | The interview, stateful. Writes `CONTEXT.md` and ADRs as terms and decisions resolve. Use whenever there is a repo under you |
| `/grill-me` | any | The same interview, stateless. For a plan, a piece of writing, a decision with no code |
| `/grilling` | any | The primitive underneath both. Works a design tree in rounds, asking the whole frontier at once with a recommendation attached to each question |
| `/prototype` | 4 | Throwaway code answering one design question you cannot settle on paper. Kept on a `prototype/` branch and pointed at from the issue |
| `/to-spec` | 3, 4 | Turns the thread into a spec and publishes it. No interview, just synthesis. Agrees the test seams with you first |
| `/to-tickets` | 4 | Splits the spec into tracer-bullet slices with real blocking edges. Handles wide refactors as expand, migrate, contract |
| `/implement` | 4 | Builds a ticket, driving `/tdd` internally, then closes out with `/code-review` before committing |
| `/tdd` | 4 | Red, green, refactor, at the seams already agreed. Reach for it alone when you want one behaviour built test-first |
| `/code-review` | 4 | Two axes in parallel: does it follow the repo's standards, and does it match what the issue asked for. Run in a fresh context |
| `/qa-plan` | 6 | Turns a run's commits into a numbered walkthrough as an issue. Findings become issues |

## On-ramps

| Skill | What it does |
| --- | --- |
| `/triage` | For issues you did not write. Moves them through a state machine and produces agent-ready briefs. Never triage tickets `/to-tickets` made |
| `/diagnosing-bugs` | The hard ones: the intermittent flake, the regression between two known-good states. Refuses to theorise until one command goes red on this bug |
| `/wayfinder` | For an effort too foggy to hold in one session. Charts decision tickets, resolves them one at a time, hands off at `/to-spec`. Never for a well-scoped feature |

## Standalone

| Skill | What it does |
| --- | --- |
| `/research` | Delegates reading to a background agent, which leaves a cited markdown file. Keep working while it reads |
| `/handoff` | A portable file, for a new harness, a new directory, or forking a side task mid-phase. Narrow by design |
| `/wizard` | For steps only a human can take: credentials, CI secrets, an unfamiliar dashboard. Generates the script instead of re-explaining the procedure |
| `/to-questionnaire` | When what blocks you is in someone else's head. The inverse of grilling |
| `/wait-what` | Mid-conversation corrective when a message did not land. Re-pitches in plain English using the project's vocabulary |
| `/retro` | Improves the agent's environment rather than the code. Navigation, automated checks, standards, tool economy |
| `/ask-matt` | The router, for when you cannot remember which of these fits |
| `unslop` | Applies to anything long before it is committed. The house style is not a preference, it is what keeps documents trusted |

## Only the core set is global

Every skill's description sits in the context window of every session in every project. All 88 cost 6,059 tokens and 65 of them could self-trigger, so `nestjs-expert` was live in a SwiftUI repo.

Core is now 32 skills at 1,317 tokens. A repo declares what else it wants in a committed `.claude/skillsets` and links them with `toolkit-link`. Eleven sets exist: web, api, data, ios, design, security, ops, marketing, onepct, personal.

Inside the container both are handled at start-up. Core is baked into the image, and whatever `skillsets` names is linked from `/opt/toolkit`.

<Note>
  **Skills and MCP servers are read once, at session start.** A skill linked into a repo during a session is not visible to that session. Start a new one inside the repo to pick it up.
</Note>
