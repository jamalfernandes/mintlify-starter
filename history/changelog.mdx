## 28 August 2026, later

### The ledger and wallet joined the workflow

`boostledger` is the third repo on the loop, and the first with real history
behind it rather than a starter. Linear project **Boost33 Ledger and Wallet**.
Eslint existed nowhere in it; turning it on found nine errors, eight of which were
rule choices or dead code and one of which became JFL-184.

### The canonical runner caught up with the repos

Two fixes had been living only in `~/DevProj/toolkit`, which syncs without its
`.git` and so had nothing to push from: the ten-second wait before asserting In
Review, and the prompt order that reviews the diff before committing rather than
after. Both are in the toolkit now, so newly scaffolded repos get them.

### Two more entries in the fix log

A page on [putting an old repo on the workflow](/fixes/an-existing-repo), which
fails differently from a fresh one, and a
[drift entry](/fixes/drift) for the case where the file-synced copy is the one
that is ahead.

## 28 August 2026

### Skills reach the container

An AFK agent had **no skills at all** — it said so mid-run: *"No local tdd skill;
I'll follow the red-green loop the DoD itself describes."* Every run in every repo
had been like this.

`toolkit-image` now builds with the toolkit root as its context so the Dockerfile
can reach `skills/`. Core is baked to `~/.claude/skills`; the full set to
`/opt/toolkit`. `onSandboxReady` links whatever `.claude/skillsets` names.

*Measured: 33 core, 65 after linking, in `boost33-identity`.*

### The commit subject parser accepts the id anywhere

The host read the ticket id only from the **front** of the commit subject. An
agent that wrote `…(JFL-174)` at the end produced a correct commit and a
completely broken handoff: no branch rename, no PR link, issue stuck.

Prompt now asks for the id at the start and says why. Parser tries anchored, then
anywhere.

### In Review is re-asserted after the PR opens

Linear's GitHub integration moves a linked issue to In Progress when a PR opens,
undoing the agent four seconds after it finished. Remapping that is a
Business-plan setting, so `main.mts` now waits ten seconds and asserts once, with
a comment explaining the correction.

### Two repos joined the workflow

`boost33-hub` and `boost33-identity` scaffolded, gated and proven end to end.
Each took a real ticket from Todo to a reviewed pull request.

### Documentation moved here

The toolkit's `docs/` are superseded by this site and now point at it.
