## 30 August 2026

### How to read a run, and the fact that nothing else is reading it

[Reading a run](/run/reading-a-run) is a new page, worked through a real three-iteration run on CFFD API — JFL-133, JFL-136, JFL-117, all green, both self-review axes satisfied. The point is that a good run still needs reading, and this one ends with `linear attach` failing on its last line.

Two structural things it records. A multi-iteration run produces **one branch, one pull request, several tickets**, and GitHub titles the PR after the last commit — so PR #11 reads `JFL-117` and carries three. And **CFFD API has no `.github/workflows`**, so nothing re-runs the suite when the PR opens and there is no red tick to be missing.

Also recorded: a filtered `-t` red is real evidence where a missing-module red is not; the self-review found a test whose comment claimed more than its assertion proved, and the agent fixed the comment rather than the assertion; and one acceptance criterion went unverified because the veraPDF step it named had been dropped in an earlier slice and never replaced.

### Two more entries in the fix log

Both on [the handoff](/fixes/the-handoff-failed), from that same run: the one-PR-per-run behaviour above, and an `attach` failure that is **not** the keyless-shell case, since the push and the PR both succeeded.

### The docs repo is `mintlify-starter`, and `workflow-docs` is archived

Two docs repos existed. The deployment was wired to `mintlify-starter` while this site's own Overview named `workflow-docs`, which had been sitting two days stale and looking canonical. `workflow-docs` is now archived and the pointer is corrected.

Diffing them first was worth it. `fixes/the-pr-shows-a-failing-build` existed only in the archived repo and would have gone with it, and it carries the finding that gating Vercel's ignore command on `VERCEL_ENV` skips the production build silently.

### The site now describes the whole route, not just the AFK loop

The Overview covered stop 5 of six. The route itself sat in `reference/build-track`, a page doing five jobs, and was described a second time in `reference/running-the-loop` with different numbering. Both are split into single-purpose pages and the journey is documented once.

The status table moved to [What is real](/history/status) with a checked date per row, because it claimed a full AFK iteration was unproven two days after four repos had run one.

## 28 August 2026, evening

### Score joined, and the ledger's scaffold merged

`boostscore` is the fourth repo on the loop, Linear project **Boost33 Score**. The ledger's scaffold went in as BoostLedger #62.

### Lint that asks a question instead of failing

Score was on Next 15 with `next lint` and no eslint config. That combination does not error — it opens an interactive menu, which in an unattended run reads as a hung agent until the idle timeout. Now `eslint .` against a flat config, wired differently from the Next 16 repos because the Next 15 preset is still eslintrc-style.

### A typecheck that only ever passed on machines that had built

Score imports five `.png` files, and the declarations that make those typecheck come from `next-env.d.ts`, which `next build` generates and `.gitignore` excludes. Clean checkouts have never typechecked. Found by the container gate, fixed with a committed `types/assets.d.ts`.

All on [putting an old repo on the workflow](/fixes/an-existing-repo), which is now eight entries and the most useful page here for the repos still to come.

## 28 August 2026

### Skills reach the container

An AFK agent had **no skills at all** — it said so mid-run: _"No local tdd skill; I'll follow the red-green loop the DoD itself describes."_ Every run in every repo had been like this.

`toolkit-image` now builds with the toolkit root as its context so the Dockerfile can reach `skills/`. Core is baked to `~/.claude/skills`; the full set to `/opt/toolkit`. `onSandboxReady` links whatever `.claude/skillsets` names.

_Measured: 33 core, 65 after linking, in `boost33-identity`._

### The commit subject parser accepts the id anywhere

The host read the ticket id only from the **front** of the commit subject. An agent that wrote `…(JFL-174)` at the end produced a correct commit and a completely broken handoff: no branch rename, no PR link, issue stuck.

Prompt now asks for the id at the start and says why. Parser tries anchored, then anywhere.

### In Review is re-asserted after the PR opens

Linear's GitHub integration moves a linked issue to In Progress when a PR opens, undoing the agent four seconds after it finished. Remapping that is a Business-plan setting, so `main.mts` now waits ten seconds and asserts once, with a comment explaining the correction.

### Two repos joined the workflow

`boost33-hub` and `boost33-identity` scaffolded, gated and proven end to end. Each took a real ticket from Todo to a reviewed pull request.

### Documentation moved here

The toolkit's `docs/` are superseded by this site and now point at it.
