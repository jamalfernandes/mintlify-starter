## What to check, and how

Until versions exist, these are the only honest answers:

| Thing | How to tell what you have |
| --- | --- |
| **Toolkit** | `git -C ~/DevProj/toolkit log -1`. If that fails, it is not a clone and cannot be trusted |
| **Canonical toolkit** | `gh repo view jamalfernandes/toolkit --json pushedAt` |
| **Container image** | `toolkit-image --check`, which reports existence and UID but **not** age |
| **Core skills** | `./install.sh --check` |
| **A repo's copy** | Compare `.sandcastle/main.mts` against the toolkit's |

## The proposal

A `VERSION` file in the toolkit, bumped when anything under `sandcastle/`, `bin/` or `sets/` changes, plus the same string baked into the image as a label and printed by the runner at start-up.

Then a run announces which machinery it used, and "is this current?" becomes a comparison instead of an investigation.

<Note>
  This is not built. It is written down because the reason it matters is fresh: a whole afternoon went into reconciling copies that a single printed number would have settled in seconds.
</Note>
