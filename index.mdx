## What this is

You write a ticket in Linear. You run one command. An agent picks the ticket up,
works in a container that can see nothing of yours except one copy of the repo,
runs the repo's own checks, commits, and opens a pull request.

It never merges. **You decide what is done.**

<Note>
This site is the reference for that system. It is private, and it is written for
you and for Claude to read mid-task — not as an introduction for anyone else.
</Note>

## The one command

```bash
cd ~/conductor/repos/<repo>
npm run afk
```

That is the whole thing. Everything else on this site is either setting that up
once, or working out why it did not do what you expected.

## Where things live

| | |
| --- | --- |
| **Tickets** | Linear, one project per repo |
| **The machinery** | `~/DevProj/toolkit` — identical everywhere, never edited per project |
| **Per-project files** | The starter repos, copied in and then owned by the repo |
| **This site** | `jamalfernandes/workflow-docs` |

The split is the filing rule: **if a file is meant to be edited by a project it
belongs in a starter, and if editing it in one project would be a bug it belongs
in the toolkit.**

## If something is wrong

Go straight to [When it breaks](/fixes/index). Every entry there is a failure
that actually happened, with what it looked like and what fixed it.

<Warning>
**Add to it when you solve something new.** The whole point is that the next
session does not rediscover what this one already worked out. Several hours were
lost today to a fix that existed in one project and never reached the others.
</Warning>
